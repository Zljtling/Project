# 架构与目录
当前规则：游戏设定.md；恢复与证据：任务进展.md；UI规范：../specs/elemental-survival/contracts/style-contract.yaml。

## 运行层
scenes/game_run.tscn → scripts/run/game_run.gd。
scripts/run/world_simulation.gd 管理基础世界/角色/模拟；run_growth.gd 管理成长与奖励接线；run_flow.gd 管理备战/部件/地牢/结算；game_run.gd 只适配三维世界、镜头和多区域服务。保留继承顺序以兼容规则测试，后续新增模块不继续向根脚本堆代码。

## 内容分组
- scripts/actors：角色、基础怪物职责与BOSS/精英；enemy_brain只处理普通怪行为。
- scripts/combat：武器伤害与发射、敌方预警/投射物；enemy_patterns统一有界生命周期。
- scripts/growth、progression：装备事务、掉落、技能、目标和开局状态机。
- scripts/world：世界布局、碰撞空间分桶、寻路、独立区域采样、设施和车辆。
- scripts/regions、scenes/regions、assets/regions：聚落、元素与tower高塔模块，按内容/共用部件分类。
- scripts/presentation：只读模拟状态的角色、武器环绕、特效、区域实例同步。
- scripts/ui：原生界面；assets/actors/cartoon 为卡通角色，assets/weapons 为武器SVG。
- scenes/validation：二维规则回归入口，不是另一套生产玩法。
- references：参考图与已弃用角色稿；docs/archive：历史记录，不参与当前规则。
- tools：检查、制作和性能工具；tests：自动回归；outputs、logs：生成产物。

## 修复与优化
1. 修复扩图后地牢与地表重叠，地牢坐标改至(24000,18000)。
2. 独立 element_zones 负责种子采样；element_field_set 统一同步全部6个领域的模型/碰撞，保留主区域作为棱镜目标兼容入口。
3. 角色模型从模拟读状态，武器环绕通过 Arsenal.attacked 信号反馈，不复制伤害逻辑。
4. 战利品按死亡类型统一调用 _drop_enemy_weapon，地牢与地表使用同一规则。
5. 共享BoxMesh缓存最多512、材质缓存最多256；被场景持有的资源不会因缓存淘汰失效。
6. 单向地牢入口释放地表敌人、房屋/元素/植被/设施/载具模型；每间地牢清除旧敌方攻击。
7. 敌方效果上限96且按寿命释放；子弹/命中/设备/金币合并沿用现有有界清理。
8. 碰撞空间分桶减少每个角色全图遍历；保持原精确碰撞、次序和寻路判定。

## 验证范围
检查工具现包含19组：原17组627项、settlement_spawn的23项、tower的33项；最新实跑结果以任务进展顶部为准。environment_presentation组需要真实Compatibility渲染器以回读MultiMesh实例，其余18组使用headless。运行参数显式使用string[]，避免PowerShell将单元素参数拆成字符。迁移检查验证实例不累加、缓存淘汰后弱引用释放和地牢释放；表现检查验证步态、攻击、暂停、限额/寿命、四灯上限、装饰避让与桥面特效高度。这些不能证明所有硬件上的长期VRAM绝不增长；仍应进行长局试玩。
同机90敌人/1953墙体同步模拟基准：优化前平均9.74ms/P95 11.18ms，分桶后平均2.61ms/P95 2.93ms。此数据不含GPU、不是游戏FPS保证。

## 角色与 UI 资产维护
- tools/build_storybook_art.py 生成原创 SVG 立绘、四方向图集、物件图标、纸张九宫格与封面。运行后由 Godot 导入，不修改参考原图。
- assets/actors/cartoon/sheets：9张1024×576图集，每格128×144，8列×4行；第0列待机，第1–6列步态，第7列蓄力，行顺序前/右/后/左。固定落脚锚点。同一角色共享Texture2D，不能逐实例复制大贴图。
- scripts/presentation/actor_motion.gd 只输出视觉帧/缩放；runtime_actor.gd 读取模拟、投影方向并应用。攻击仍由arsenal/enemy_patterns决定。
- runtime_effects.gd 继续批量绘制；补充的脉冲最多64、枪口最多12，按寿命释放；危险物仍受96上限约束。
- assets/ui/icons：128×128彩色物件图标，技能/备战/装备栏复用。game_theme.gd 维护纸底与状态样式；forge_panel.gd 只选材料并调用原成长事务。
- tools/capture_ui_review.gd / capture_combat_review.gd 为复核工具，输出真实引擎界面/录像，不是生产启动路径。
## 2026-11-03 光照与环境表现增量
世界光照集中于 scripts/presentation/world_lighting.gd，运行场景只装配。灯具通过 ambient_lamp_sockets 标记参与附近四盏复用灯的选择，不给每个建筑分配动态灯。渲染器仍为Compatibility。
环境动画使用delta驱动时钟，随游戏暂停；风动植被和花草碎石用MultiMesh批绘制，火区火星固定42实例/区域。额外领域由element_field_set拥有，单向地牢释放由runtime_world统一负责。新增材质/节点不得持有已释放地表模块的全局强引用。
本轮627项通过及六处实景截图、桥上战斗录制证据见任务进展顶部。tools/capture_combat_review.gd -- --bridge录制桥面交战；主场景 -- --capture-game=fire-close 输出正常游玩距离火区截图。调试参数不改变正常F5开局路径。

## 2026-11-03 高塔增量
- scripts/regions/tower/tower_layout.gd：唯一的本地实体布局、四门、精英与奖励锚点；world_layout与三维模型同时读取。新增塔楼/墙柱时先在此定义实体，禁止只在美术脚本中添加挡路部件。
- scripts/regions/tower/tower_region.gd：塔楼、拱券、廊顶、旗帜、有限灯光插槽及防遮挡参数；只读角色/镜头，不负责伤害或掉落。
- assets/regions/tower：石材局部透视与旗帜着色器。模块仅持有五份石材变体，随模块释放。
- runtime_world：替换塔体、同步整体下沉；meadow_dressing预留三处迁移站点，避免草穿过庭院。
- tests/tower_checks.gd：真实模型碰撞比对、通行、寻路、射线、暂停与连续迁移；tools/capture_tower_review.gd输出overview/court/treasury/gallery/sink五幅实际运行截图。
