# 美术接入与替换

当前使用占位图形和基础 HUD 验证玩法，没有采用正式角色、场景或特效素材。后续继续做俯视角 2D 时，可以逐步替换表现资源，保留移动、索敌、伤害、合成、材料消耗与死亡判定。

## 当前已做的分离

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 玩家与敌人逻辑 | `scripts/actors/` | 移动、受伤、攻击行为、状态与 BOSS 行为 |
| 角色外观资源 | `data/appearance/` | 占位类型、静态贴图、SpriteFrames 动画、显示缩放和偏移 |
| 角色绘制 | `scripts/presentation/actor_visual.gd` | 读取角色状态，播放外观动画、显示受击反馈与状态标识 |
| 地图表现 | `scripts/presentation/world_visual.gd`、`growth_world_visual.gd`、`buildings_visual.gd` | 地板、高塔、村庄、房屋、领域、设施、掉落物与技能部署物；屋顶靠近时透明 |
| 战斗反馈 | `scripts/presentation/combat_visual.gd` | 子弹、命中特效、范围效果与集火标记 |
| 界面 | `scripts/ui/` | HUD、菜单、字体和布局 |
| 武器配置 | `data/weapons/` | 武器基础伤害、攻击间隔、射程等参数 |

角色和敌人的占位绘制已从控制脚本中移出，独立子节点负责显示。角色外观资源可由各实例的 `appearance` 属性指定。场景和战斗表现也已移到独立脚本，仍通过读取玩法状态来显示，需要在接入 TileMap、动画场景或粒子时逐项替换这些表现节点。

## 替换角色或小怪

1. 将自有或有使用许可的素材放入 `assets/`，让 Godot 导入。
2. 在 Godot 文件系统中打开 `data/appearance/player.tres` 或 `enemy.tres`。
3. 静态图使用 `texture`；有动画时使用 `animations`，指定一个 `SpriteFrames` 资源。有动画资源时优先使用动画。
4. 动画默认名称为 `idle` 和 `run`，也可以通过 `idle_animation` 和 `move_animation` 指定其他名称。
5. 使用 `sprite_scale` 与 `sprite_offset` 对齐角色脚底和视觉大小。

显示大小与玩法范围分开处理。仅更换贴图不会自动改变碰撞半径、移动速度或攻击射程。若新素材需要明显改变角色体型、武器长度或攻击动作，需要相应调整碰撞、攻击判定和动画时机，但不必因此重写整套战斗架构。

目前还没有完整的多方向动画、骨骼动画或攻击动作同步系统；选定具体素材后再按需要接入。UI 也还没有完整的换肤资源包，后续主要在界面层统一调整。

## 替换场景与特效

地图逻辑保留领域中心、半径、设施位置和高塔状态。新的场景表现应读取这些状态，避免把毒气伤害写进粒子脚本、把塔的迁移判定写进动画脚本。

本轮增加 `scripts/world/world_layout.gd`，保存村庄、房屋、墙体、城门与寻路网格。角色移动、怪物绕路和武器视线使用同一份几何；房屋与高塔表现仍在 `presentation` 层。换房屋、城墙或台阶素材时，应对齐门口和墙体占地，保留可通行的开口。当前 2.5D 通过墙体立面、台阶、阴影与遮挡表现，尚未接入正式等距素材；如果改投影角度或增加独立楼层，需要适配坐标和遮挡规则。

Jeff FX 可以用于制作或导出特效。接入时由战斗或状态触发对应表现，命中与伤害仍由战斗系统处理；不要依赖屏幕上某个特效是否仍在播放来决定是否命中。

现在也有 PixelFX 的 244 套原生动画资源，位于 `assets/pixelfx/`，运行适配器为 `scripts/presentation/pixel_fx_player.gd`。技能图标位于 `assets/ui/icons/`，可以单独替换。具体用法见 [Godot AI 与特效库](GodotAI与特效库.md)。

只在 2D 范围内更换像素、简笔或手绘素材，主要涉及表现层、资源和少量适配。若改为 3D、真实跳跃平台或不同高度的寻路规则，则涉及摄像机、物理与寻路，需要另行评估。

## 已验证

自动检查已分别用内存中的测试贴图与 `SpriteFrames` 替换玩家外观，确认能够创建 `Sprite2D` 和 `AnimatedSprite2D`，不修改玩家控制脚本。原有战斗、毒区、暂停和高塔检查也继续通过。
