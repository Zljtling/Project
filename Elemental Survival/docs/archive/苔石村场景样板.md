# 苔石村场景样板

2026-11-02：用户确认“被元素灾变侵蚀的村镇与遗迹”，采用立体建筑和地形、像素人物的混合表现，参考《八方旅人》的空间与像素质感。动作生存玩法优先保证战斗可读性，不照搬重景深或较低机位。

用户已采纳第二版建模，后续场景沿用这一美术与模型基准。下一步进入完整地图布局讨论。

最新：所有区域目录统一到 `regions`。苔石村的独立入口与六区域合并入口共用 `taishi_module.tscn`，房屋门槛已改成与室外齐平。复核入口、扩充规模及室内箱子见《区域复核与目录》。

## 启动

在 Godot 打开 `scenes/regions/taishi/taishi_village.tscn`，按 F6 运行当前场景；也可在项目根目录运行 `./tools/play_village.ps1`。F5 仍运行原完整流程试玩。

WASD 按镜头方向移动，Q/E 拉远/拉近镜头，Home 回到路口。五栋房屋均有南北入口。靠近时屋顶、前墙和朝镜头的右侧墙隐藏，离开后恢复，墙体碰撞始终保留。树冠对人物周围局部透视，树干仍有碰撞。

第二版按用户提供的八张参考图调整为：叶簇分层、绿地色块、石板路和带细节的像素建筑。现有五栋房屋、22 棵树、六盏路灯，新增老井、长椅、木桶、手推车、遗迹拱门与池塘。房屋增加窗台、百叶窗、屋檐、老虎窗、烟囱帽；包含锻造招牌和两种雨棚变体。新增密集草丛和野花，使用 MultiMesh 合批。参考图只作为风格依据，未裁图作为游戏贴图。

人物仍是临时比例参照，尚非正式角色动画。地表目前平坦，用于验证通行；多高度地形、战斗与完整地图尚未迁入。本版仍是开发中样板，不代表达到参考图的完整美术质量。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `scenes/regions/taishi/taishi_village.tscn` | 房屋摆放、世界环境与太阳光 |
| `scripts/regions/taishi/taishi.gd` | 样板组合入口，连接目标与镜头，说明界面和截图 |
| `scripts/regions/taishi/layout.gd` | 建筑、树木、池塘位置及散布排除范围 |
| `scripts/regions/taishi/ground.gd` | 地表、石板路、批量草丛与野花 |
| `scripts/regions/taishi/props.gd` | 井、灯、箱桶、长椅、手推车、遗迹与池塘 |
| `scripts/regions/shared/tree.gd` | 立体树干、枝干、分层像素叶簇和树干碰撞 |
| `scripts/regions/shared/foliage_visibility.gd` | 每帧更新一份共享树叶材质的目标位置，支持窗口缩放 |
| `scenes/regions/shared/stone_house.tscn` | 可实例化的房屋资源，支持屋顶颜色参数 |
| `scripts/regions/shared/house.gd` | 房屋局部结构、实体碰撞与进出遮挡 |
| `scripts/regions/shared/model_parts.gd` | 网格与材质构建函数，无游戏状态 |
| `scripts/regions/shared/review_traveler.gd` | 样板移动、重力、像素方向动画 |
| `scripts/regions/shared/review_camera.gd` | 跟随指定目标与调整距离，不查找全局玩家 |

房屋在运行时由参数生成。门洞两侧墙体同时产生可见网格和碰撞，避免表现与物理各存一份尺寸。遮挡通过 Area3D 的进入/离开信号驱动，不让总场景逐帧遍历房屋。探测范围比室内略大，提前显示入口；这是切换式隐藏，尚无透明渐变。

树冠使用统一共享材质，按归一化屏幕位置与实际片元深度对人物前方的叶片做局部像素溶解。窗口采用 canvas_items 拉伸，CPU 投影像素与 3D 渲染分辨率可能不同，禁止直接传绝对像素。半径随镜头距离变化；重叠树冠共用同一透视窗口。透视不修改实体、不清空树干碰撞，也不切掉树木的投影。树叶为面向镜头的像素叶簇，并非完整可任意旋转观察的三维叶片模型。

池塘使用独立实体边界防止直接走在装饰水面上。地形外围设置边界，避免样板角色走出地表后下落。

碰撞层：1 为地表和静态障碍，2 为人物。室内区域只检测第 2 层。将来怪物加入时，应为遮挡检测分配独立玩家标识或层，不能让怪物触发玩家的屋顶显示。

## 模型和贴图

`assets/regions/shared/` 保存原创贴图。先运行 `tools/build_village_textures.py` 生成角色和基础素材，再运行 `tools/build_village_nature.py` 覆盖精修表面贴图并生成像素叶簇、草丛。均使用固定随机种子，Python 标准库即可运行。纹理使用最近邻采样，避免像素被平滑。地面和水面使用独立 shader，避免向总入口加入逐帧装饰动画。

`assets/regions/shared/models/` 包含四种房屋的可编辑 GLB 交换模型，可导入 Blender 或 Godot。通过 Godot 执行 `--headless --path . --script res://tools/export_village_models.gd` 可重新导出。GLB 只导出几何和材质，不含房屋碰撞、屋顶触发与脚本；运行时房屋以参数化场景为准。GLB 工具链不保证保留 Godot 特有的三平面贴图设置，正式跨软件贴图还需 UV 展开。

## 后续接入边界

现有二维游戏入口、角色控制和场景绘制没有加入三维分支。样板未复制装备、战斗、世界周期、成长等规则。后续迁移时：

1. 先从旧 Node2D 游戏脚本中抽出与坐标和渲染无关的规则；二维与三维入口共同调用这些规则。
2. 地表坐标统一映射为 X/Z 平面，高度只使用 Y；转换集中在一个适配模块，禁止业务脚本自行交换轴。
3. 建筑布局由数据提供，模型只解释局部结构；增加建筑变体应新增资源，不把不同建筑的分支塞入总入口。
4. 迁移移动、视线、投射物和寻路时统一使用同一套三维物理几何，再逐项接入周期与领域。当前样板不假装已经与旧战斗兼容。

不预建 ECS、全局事件总线或通用框架；有实际共用需求再抽象。草丛与野花已合批；建筑和道具保留独立网格，扩大地图时再按测量结果合批与分区加载。房屋变体目前只改变装饰，共用通行结构；不同平面布局应新增建筑资源。

## 验证

`tests/village_checks.gd` 含 25 项检查：双门通行、墙体阻挡、隐藏墙碰撞保留、离开恢复、地表支撑、镜头跟随、像素帧布局，以及树冠目标坐标与开关、树干碰撞、池塘/地图边界、新建筑入口、植被合批和树木不落在水中，已纳入 `tools/check_project.ps1`。Shader 的最终透视效果额外通过有图形设备的开启/关闭截图对比检查。

启动时追加 `-- --capture-village` 可导出 `outputs/village-preview.png`；追加 `-- --capture-village-interior` 可导出室内图并退出。应使用有图形设备的普通运行模式，headless 不支持画面检查。受当前执行环境用户目录权限限制，Godot 会报告 shader cache 无法创建；不影响截图与物理检查。

其他截图参数：`--capture-village-tree` / `--capture-village-tree-solid` 生成同一树下位置的透视开启/关闭对比；`--capture-village-garden` 查看池塘区域。
